# 0011 – The repository holds three units — the OutloudKit package, the macOS app and the iOS app — and XcodeGen generates the apps' Xcode projects

- Status: accepted
- Date: 2026-10-22

## Context

ADR 0002 sets one shared Swift package and one module per platform. Each
platform module ships as an app of its own: the macOS app as a GitHub
download (ADR 0009), the iOS app on its own. `AGENTS.md` §"Repository
layout" puts every deployable unit — an app, a service, a library — in a
directory of its own with its own area file, its commands run from that
directory.

An Xcode project file (`project.pbxproj`) is a generated-looking file
that Xcode rewrites on many edits; two sessions editing targets at the
same time produce merge conflicts in it that are resolved by hand.
XcodeGen
generates the project from a short `project.yml`; ghost-pepper uses it.

Rejected alternative: one hand-kept Xcode project with both app targets
and the package — a faster start, but its project file conflicts under
parallel edits, and the units would share one directory.

Proposed on 2026-10-22 with the plan of the first version; the user
changed only the oldest supported versions (ADR 0012).

## Decision

The repository holds three units, each in a directory of its own with its
own `AGENTS.md`, `CLAUDE.md` and `precommit` command:

- `OutloudKit/` — the shared Swift package (ADR 0002), built and tested
  with SwiftPM;
- `apps/macos/` — the macOS app;
- `apps/ios/` — the iOS app.

Each app's Xcode project is generated by XcodeGen from its `project.yml`.
The generated `.xcodeproj` is not committed; it is regenerated by the
app's `precommit` command and whenever `project.yml` changes.

## Consequences

- `project.yml` is the source of an app's build settings; nobody edits a
  generated project by hand, and no test has to guard it because it is
  never committed.
- Opening an app in Xcode needs `xcodegen generate` first.
- The apps depend on `OutloudKit` as a local package.
