# Architecture

This document owns the system's components, the communication paths between
them, the API and channel contracts, the data and sync formats, and the auth
model. It describes what *is*; why it is that way lives in `docs/adr/`, and
the rules it must keep to live in `docs/ARCHITECTURE_PRINCIPLES.md`.

## Components

Outloud is written in Swift with SwiftUI, for iOS and macOS, with one
shared Swift package and one platform module per platform (ADR 0002),
for iOS 27 and macOS 27 and later (ADR 0012). Each lives in a unit of its
own — `OutloudKit/`, `apps/macos/`, `apps/ios/` — and the apps' Xcode
projects are generated by XcodeGen (ADR 0011). There is no server.

### Shared Swift package (`OutloudKit/`)

Three targets (ADR 0013):

- **`OutloudKit`** — the core. `ModelCatalog` pins the models;
  `ModelStore` is the one owner of the model files (download, check,
  delete; ADR 0010, ADR 0014); `ModelLibrary` presents their states;
  `Engines` loads the transcription model once — `ParakeetTranscriber`
  (FluidAudio); `AppleCleaner` cleans up with Apple's on-device model
  (Foundation Models), and `CleanupAvailability` says whether it can;
  `DictationPipeline` turns samples or text
  into a `DictationOutcome`; `DictationController` runs one dictation from
  the recording to the history, the one the user sees, and processes the
  dictations ended in or handed to the background (ADR 0027) one after
  another with it; `OptionCommandChord` decides the ⌥ ⌘ chord from the
  modifier flags, and `ReturnPaste` where and when a dictation that follows
  its field is pasted, and which ones wait, the platform
  reading the keys and the focused field; `AudioRecorder` captures the microphone as
  16 kHz mono samples; `HistoryStore` is the one owner of the history's
  files and `HistoryModel` presents them; `OutloudSettings` keeps the
  shared settings in `UserDefaults`.
- **`OutloudUI`** — the tokens and components of `docs/DESIGN.md`.
- **`OutloudCLI`** (`outloud`, macOS only) — lists, downloads and deletes
  the models in the cache and dictates an audio file; a developer tool.

Must never own: anything platform-specific beyond the audio session —
hotkeys, overlays, App Intents, pasting.

### iOS platform module (`apps/ios/`)

Owns the screens, the App Intents and the clipboard (ADR 0003): the
"Dictate with Outloud" intent opens the app and starts a recording; the
widget extension `OutloudWidgets` offers it as a control to the Action
Button, the Control Center and the Lock Screen (ADR 0017), and the intent
is compiled into both targets from `apps/ios/Shared/`. Two intents run in
the background, where iOS does not let the app write the clipboard
(ADR 0018), and return their text for the shortcut to copy: "Start or Stop
Dictation with Outloud" (`ToggleDictationIntent`, an `AudioRecordingIntent`
and `LiveActivityIntent`) starts a recording with an audio session that
mixes with other audio — iOS refuses an exclusive one in the background —
and a Live Activity (`DictationLiveActivity` in the widget extension), and
its next run ends it and returns the cleaned text (ADR 0022);
`BackgroundDictation` runs it and keeps the activity in step with the
dictation. "Clean Up Text with Outloud" cleans up text it is given. Apple's
model may be used in the background, within a budget (ADR 0019). One
`AppModel` serves the interface and the intents.

### macOS platform module (`apps/macos/`)

Owns the push-to-talk hotkey (Carbon hot keys, which report the press and
the release without the Accessibility permission), the menu bar panel,
the recording overlay — a non-activating panel, so the target app keeps
the focus — and auto-paste (ADR 0004). It is distributed as a download
from GitHub, signed with Developer ID and notarised, runs outside the App
Sandbox, and updates through Sparkle (ADR 0009, ADR 0016).

### Models

Transcription and cleanup run on the device, on iOS and macOS.
Transcription uses a downloaded open model (ADR 0005, ADR 0006): Parakeet
v3 with FluidAudio 0.17.7 (`AsrModels.loadLocal`, the CoreML conversion
`FluidInference/parakeet-tdt-0.6b-v3-coreml`). The cleanup uses Apple's
on-device model through Foundation Models (ADR 0019): it runs in a system
process, needs Apple Intelligence switched on, and no download.

On macOS, downloaded models are stored in the Hugging Face hub cache, in
the hub's own layout, where other tools reuse them (ADR 0010); on iOS, in
the app's own container, in the same layout (ADR 0009). A model's files download at once.
On iOS they run in a background `URLSession`, which iOS goes on with while
the app is suspended or ended, and which treats files started from the
background as postponable — hence all at once, in front. Each task carries
its destination relative to the home folder, since an iOS container can
move, so that a file that finished meanwhile is checked and linked like any
other. `ModelLibrary` keeps the downloads the user started and that have
not ended in `UserDefaults`, and both apps go on with them at launch. A
request is allowed onto an expensive network only when the user allowed
cellular data.

Before the cleanup model sees a transcript, `HesitationFilter` removes
hesitation sounds ("äh", "uh"; "um" and "er" only where a comma sets them
off, since they are German words) and, in a German text (by
`NLLanguageRecognizer`), "also" at the start of a sentence: the model,
left to drop it at the start of two sentences in a row, repeats the first.
Each cleanup opens a fresh session whose
transcript holds the instructions of `CleanupPrompt` and the worked
examples as earlier turns; the transcript follows, framed as
`<USER-INPUT>`, answered with greedy sampling. The answer is discarded —
the transcript becomes the result — when it times out (20 s), is empty,
is much longer than the transcript, keeps well under half of its words
(the model dropped a request that followed a statement), repeats a run of
five words more often than the transcript (the model lost its place and
wrote a passage again), or the model refuses (`CleanerError`:
in the background Apple limits how often an app may use it); transcripts
over 4,000 characters are not cleaned up. The prompt's test inputs and
results are in `plans/APPLE_CLEANUP.md`.

## Communication paths

Besides Sparkle's update check on macOS (the appcast and update zips from
the GitHub releases, ADR 0016), the only network traffic is the model
download: HTTPS `GET` of
`https://huggingface.co/<repository>/resolve/<revision>/<path>`,
following Hugging Face's redirect to its CDN; nothing is uploaded.

## Contracts

- **Model cache** — the Hugging Face hub layout (ADR 0010):
  `models--<org>--<name>/blobs/<etag>`, relative symlinks in
  `snapshots/<commit>/`, per-file locks in `<root>/.locks/`.
- **History** — `index.json` (an array of entries: `id`, `createdAt` in
  ISO 8601, `transcript`, `cleaned`, `hasAudio`) and one 16-bit mono
  16 kHz WAV file per entry with audio, named `<id>.wav`.
- **Settings** — `UserDefaults` keys `cleanupEnabled`, `retentionPeriod`,
  `transcriptionModel`, `hasCompletedSetup`, `pausesPlayback`, and on
  macOS `hotkey` and
  `autoPaste`. Opening at login is the system's login item
  (`SMAppService`), not a stored setting.
- **Cleanup timing** — `UserDefaults` keys `cleanupCharacterSamples`, the
  last 20 cleanups after a recording as `[characters, seconds]` pairs —
  the characters of the transcript —, to which a line of a start plus a
  time per character is fitted (Theil–Sen, the slope only from pairs at
  least 100 characters apart, else the guessed 0.008 s), and `cleanupPrompt`, the
  SHA-256 of the prompt and examples they were measured with; a different
  prompt starts them anew. Nothing asks Apple's model for the tokens: the
  count discards the prewarmed session and doubles the cleanup. 0.2.0
  kept a moving average in `cleanupSeconds`, 0.2.1 the last durations in
  `cleanupDurations`, 0.2.2 to 0.3.0 `[tokens, seconds]` pairs in
  `cleanupSamples`; all are removed at the next cleanup.
- **Transcription timing** — `UserDefaults` keys `transcriptionSamples`,
  the last 20 transcriptions after a recording as `[audio seconds,
  seconds]` pairs, fitted the same way with pairs at least 5 s apart, and
  `transcriptionModel`, the id
  of the model they were measured with; another model starts them anew.

## Trust boundaries

### Microphone

Both apps record only on a user action — the trigger (ADR 0003,
ADR 0004): on macOS while the hotkey is held, on iOS between the start
and the stop of a recording.

### Auto-paste into other apps (macOS)

The macOS app inserts text into the focused field of another app, with
the Accessibility access the user granted, only after the hotkey was
released and only when the focused element takes text; a secure (password)
field never receives it. The clipboard's previous content is restored
afterwards. Without the access, the result stays on the clipboard
(ADR 0004).

Every dictation that starts in a text field, with auto-paste on, follows
that field (ADR 0026, ADR 0027): the app keeps the field focused when the
recording started — the Accessibility element, its process, and an
identity of the window's title, the element's identifiers and, inside web
content, the page's title and address, since an Electron app keeps one
element across its conversations. While such a result is processed or
waits, the app reads the focused element of the app in front every 0.3 s,
not while a recording is held; the result is pasted with the same ⌘V only
when element and identity equal the remembered ones. A dictation started
in a field that already has one follows the next other field focused, and
is copied when none was by its end (`ReturnPaste` in `OutloudKit`
decides). Outloud never activates an app to paste and posts no other key;
it activates another app only to hand the activation back when the user
closes the menu bar panel (ADR 0028). Writing
into an app in the background through Accessibility was measured and
rejected (ADR 0026).

### Model downloads

Model files come from outside and are loaded into the model runtimes. On
macOS they lie in a directory shared with other apps, which every process
of the user can write to. Every file is checked against the hash the
catalogue pins, after the download and before loading when it changed
(ADR 0014).

### The transcript as model input

A dictated sentence can read like an instruction. The cleanup model is
told not to follow instructions in the input, gets the transcript framed
as user input, is told to repeat questions and requests like every other
sentence, and an answer that is much longer or much shorter than the
transcript is discarded (`OutloudKit/AGENTS.md` §"Security").

## Auth

None. Outloud has no accounts and talks to no service but the anonymous
model download.

## Data

A recording is not stored permanently by default (`docs/SPEC.md`
§"Transparency and privacy").

The history keeps, per result, the uncleaned transcript, the audio of the
recording and the cleaned version, on the device, in
`Application Support/Outloud/History/`, protected until the device is
first unlocked after starting (so that a dictation on a locked iPhone can
still keep its result), for the period the user sets; expired entries are removed at
launch, every five minutes while the app runs, and when the period
changes (`docs/SPEC.md` §"History"). Voice recordings and the texts
dictated are personal data. The logs carry durations, lengths and error
kinds of the cleanup, never a text.

## Deployment shape

Two apps on the user's devices; nothing runs elsewhere.
